# 보안길잡이 프로젝트 지침 (요약)

v1.14 · 2026-11-07 · 중복 정리(규칙별 원본 문서 지정), Java 25 재확정, Lombok 허용 목록 사용. 이 문서는 프로젝트 설정 '지침' 칸에 등록하는 요약본이며, 상세 규칙과 충돌하면 원본 문서가 우선한다. 개정 이력은 PROJECT_CONTEXT.md 7장.

## 프로젝트

보안길잡이(영문 서비스명 **SecurityAdvisor**, 백엔드 패키지 `kr.securityadvisor`): 정보보안을 모르는 공공기관 담당자가 AI 인터뷰로 방화벽신청서·보안성검토 신청서 초안을 만드는 서비스. 서류 생성기가 아니라 현업↔전문가(정보보안·ICT인프라 담당자) 지식 중계 플랫폼. 2026 공공 AI 대전환 챌린지 세션1 출품 — 본 제출 11.11, 예선 11.13~17, 결선 11.25. 1차 범위는 서류 2종·역할 4종(일반 사용자/정보보안/ICT인프라/기관 관리자) 고정, 11.08 기능 동결. 운영 기관은 설치당 1곳 고정(기관 테이블 없음, 기관명·코드는 `.env`).

업무 규칙(4단계 절차·차수 반환·종결/철회, 사업 건 1:N 신청, 운영 업무 도메인 6종, 운영 기관, 불변식 36개, 상태)의 원본은 FUNCTIONAL_SPEC.md다.

## 작업 전 버전 확인 (필수)

1. 작업을 시작하기 전에 PROJECT_CONTEXT.md 5장 **기준 버전 표**를 읽고, 이 지침(설정 '지침' 칸)과 참조할 문서 머리말의 버전·개정일이 표와 같은지 확인한다.
2. 다르면 **버전·개정일이 높은 쪽을 최신으로 본다**(버전은 숫자로 비교: v1.10 > v1.9). 지침 칸이 문서보다 낮으면 문서를 따르고, 작업 결과 첫머리에 "지침 칸 vX → 최신 vY 교체 필요"를 알린다.
3. 같은 문서가 여러 곳(프로젝트·저장소·공유 문서·zip)에 있고 내용이 다르면, 임의로 하나를 골라 진행하지 말고 차이를 먼저 보고한다.
4. 문서를 개정할 때는 PROJECT_RULES.md 7-1의 **문서 개정 절차**를 따른다. 새 규칙은 원본 문서 한 곳에만 쓰고 다른 문서에는 링크만 둔다(예외: 이 지침의 요약).
5. 프로젝트 문서는 문서마다 한 경로에만 둔다 — 규칙 문서는 프로젝트 루트, 이 지침은 `claude/INSTRUCTIONS.md`, 작업 목록은 `claude/BACKLOG.md`.

## 불변 원칙 (모든 산출물 — DDD의 도메인 불변식으로 코드에서 강제, 개발자용 원본은 AGENTS.md 11장)

1. AI는 제안만, 확정은 항상 사람이 한다. AI 값을 확정 사실처럼 표시 금지. 3단계 AI 최종 초안의 보완분도 미확정.
2. 모든 값은 출처 4종(사용자 답변/AI 추론+근거/담당자 입력/담당자 확인)을 가진다. 출처 없으면 "담당자 확인 필요".
3. 지식(공개자료 RAG)과 사실(기관 비공개 컨텍스트·담당자)을 분리. AI가 내부 IP·시스템명을 지어내지 않는다.
4. 상태 의미 구분: 검토 완료 ≠ 실제 처리 완료, 할당 완료 ≠ 협의 완료, 서류 확정 ≠ 방화벽 적용, 초안 ≠ 게시본 ≠ 제출본.
5. 권한·업무 전이·버전 검증은 서버가 최종 판단. 클라이언트 role·기관 값 신뢰 금지(모든 계정은 운영 기관 1곳 소속).
6. 차수 반환·종결·철회는 사유 필수, 기존 값·이력 보존. 반환 시 보완 필요 항목만 강조 표시.
7. 한 신청의 상태 전이는 같은 사업 건의 다른 신청을 바꾸지 않는다. 공통 정보 변경은 미제출 신청만 재검토 표시, 제출본은 불변.

## 절대 금지

- 실제 내부 정보(내부망 IP·서버·자산·비공개 규정·실존 개인정보)를 코드·커밋·모의데이터·스크린샷·영상·문서에 넣는 것. 전부 합성 데이터만.
- 비밀값(API 키 등)의 코드·Git·DB 평문 저장. 환경변수/키 참조만.
- 실행하지 않은 검사·테스트를 통과로 보고하는 것. 미구현·미검증은 그대로 표기.
- 11.11 마감 후 공공GitLab 산출물 수정.

## 기술 스택과 방법론 (원본: AGENTS.md 1·5장)

Next.js(App Router)+React 19+TS 5.9+TanStack Query / **Java 25(LTS)**+Spring Boot 4.1+Gradle(Kotlin DSL)+Spring Data JPA+Lombok(허용 목록만) / Spring AI 2.0(공통 LLM 어댑터 뒤, LLM 2종 이상 구동) / PostgreSQL 17+Flyway+pgvector / Docker Compose. 방법론은 DDD 전술 패턴(바운디드 컨텍스트·유비쿼터스 언어·도메인 메서드·불변식). API는 RESTful(자원 명사 경로, 상태 전이는 하위 자원 POST/PUT, ProblemDetail). 코딩 스타일은 Google 가이드, 보안은 KISA 시큐어코딩 가이드.
