## 변경

신청 상세·이전 제출본·문서함은 동일한 DocumentActions를 사용한다.
미리보기의 별도 documentText 조합을 제거하고 POST generated-documents의
GeneratedDocumentResponse를 검증해 서버 제목·구분·버전·섹션·표시값·출처·확인 상태를 보여 준다.
다운로드는 미리본 generatedDocumentId의 PDF를 사용하고 서버의 한글 파일명을 보존한다.
HTML/Markdown을 실행하지 않고 텍스트로 표시한다.

같은 원본의 생성 요청과 PDF 응답을 세션 내 공유한다. 신청·사업·최종 초안 변경과
업무 상태 변경 시 새 문서를 준비하며, 미리보기 안의 다운로드는 표시 중인 문서에 고정된다.
PDF 실패 후 재시도는 문서를 다시 생성하지 않는다. 로그아웃 시 기존 공통 Query 캐시 초기화를 따른다.
제출본 식별자·본문이 누락된 4단계 신청은 현재 초안으로 대체하지 않는다.

모의 서버는 같은 문서 생성·목록·상세 계약을 제공한다. 실제 PDF 생성은 Back 연결 환경에서 제공하며
모의 환경에서는 기존과 같이 503 및 안내 문구를 반환한다.

- 도커 최신 main 동기화 후 기능 브랜치를 빌드하여 실제 화면 검증
- 신청 25 최신 제출본 7: 문서 7 / 확정본 v2를 미리보고 `확정본_25_v2.pdf` 17,691바이트 다운로드
- 같은 신청의 이전 제출본 6: 문서 8 / 제출본 v3. 과거 허용 목적·최종 서술을 유지하며 확정본으로 잘못 표시하지 않음
- 신청 28: 문서 9 / 초안 v1 확인 → 화면에서 합성 허용 목적 수정·저장 → 문서 10 / 초안 v2에 수정 반영 및 PDF 다운로드
- 문서함 검색으로 신청 25 선택 → 문서 11 / 확정본 v4 미리보기·동일 버전 다운로드
- 제출본 6·7 JSON을 작업 전 기록과 대조: 불변
- 실제 내려받은 확정본·이전 제출본·초안 PDF를 이미지로 렌더링해 한글·표·페이지·최종 보고서 표시 확인
- 390×844 화면: 가로 넘침 없음, 본문 읽기·다운로드 가능
- Enter 다운로드, Tab/Shift+Tab 모달 내 순환, Escape 닫기 및 미리보기 버튼 초점 복귀 확인
- 자동 검사: 서버 응답과 로컬 값 분리, XSS 텍스트 처리, 잘못된 문서 응답 거부, 중복 생성 방지,
  수정 후 새 문서, 생성/파일 오류 재시도, PDF 형식·파일명 검증

## 범위

미리보기는 서버 정식 문서의 섹션을 읽기 쉬운 화면으로 표현하고, 내려받는 파일은 그 문서의 서버 PDF다.
PDF 페이지 자체를 브라우저 안에 임베드하는 기능은 추가하지 않았다.
합성 신청 28의 허용 목적에 문서 검증 문장만 추가했다. 실제 장비와 기존 확정 신청의 업무 값은 변경하지 않았다.
