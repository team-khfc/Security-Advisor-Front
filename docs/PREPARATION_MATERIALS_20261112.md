# 사업 조건별 준비자료 관리

## 사용 순서

신청 상세의 **사업 조건별 준비자료 · 첨부 및 검토 상태**를 펼친다.

1. 사업 인터뷰의 개인정보·외부 연계·대외 서비스·외부 업체 답변을 저장·확인한다. 클라우드·AI 사용 여부는 준비자료 영역에서 별도로 선택한다.
2. 공통 4종(사업계획서, 제안요청서·과업 범위, 시스템·망 구성도, 자체 보안대책)과 조건별 6종의 권고 자료를 확인한다. 미확인 조건은 미해당으로 추정하지 않는다.
3. 파일을 선택한 후 **선택한 자료 업로드**를 누르고, 해당 자료의 파일 목록에서 선택해 **선택 자료 연결·교체**한다. 기존 첨부도 재사용할 수 있다. 항목당 최대 10개이며 파일 자체는 삭제하지 않는다.
4. 협의 단계부터 현재 배정된 해당 분야 담당자가 원문을 확인하고 검토 중·보완 필요·확인 완료를 저장한다. 보완 사유는 필수다. 신청자와 관리자는 확인 완료를 대신할 수 없다.
5. 연결·교체하면 검토 중으로 바뀐다. 관련 사업 조건이 달라지면 기존 확인은 재검토 대상이 된다. 변경자·시각·사유·파일 연결 기록은 신청 이력에 남는다.

## 범위와 권한

- 자료 목록은 준비를 돕는 권고 목록이며 법적 의무 판정이나 협의·제출 요건을 자동 추가하지 않는다.
- 상태는 미첨부 / 검토 중 / 보완 필요 / 확인 완료다. 조건 적용 여부와 자료 상태는 별개이며 현재 미해당 자료의 과거 연결도 보존한다.
- 신청자는 본인 신청, 담당자는 현재 자기 분야에 배정된 신청만 접근한다. 관리자 조회는 허용하되 자료 변경은 금지한다.
- 자료 연결은 작성·협의·신청자 최종 검토 단계에서 가능하다. 자료 검토는 협의·신청자 최종 검토 단계에서 해당 분야 담당자가 수행한다. 제출·종료 후 변경은 차단한다.
- 준비자료 현황은 현재 상태이며 확정된 제출본·최종 PDF의 스냅샷과 별개다. 기존 신청에 연결 기록이 없다면 첨부 파일을 특정 항목과 임의 연결하지 않는다.
- 조건 변경은 보수적으로 기존 자료 검토를 다시 요구한다. 값이 원래대로 돌아와도 이전 확인을 되살리지 않는다.
- `expectedRevision`과 사업 조건 지문이 모두 맞아야 저장한다. 충돌 시 입력을 보존하고 **최신 목록 확인** 후 차이를 확인해 다시 저장한다.

## API

- `GET /api/security-requests/{id}/preparation-materials`
- `PUT /api/security-requests/{id}/preparation-materials`: ATTACH / REVIEW / CONDITIONS
- `POST /api/security-requests/{id}/preparation-materials/files`: 명시적인 multipart 업로드
- 기존 원문 보기·다운로드 API와 준비자료 변경 감사 이벤트를 함께 사용한다.
- 신규 Flyway 마이그레이션으로 신청별 검토 묶음을 저장한다. 이전 신청 데이터는 수정하지 않는다.

## 검증 (2026-11-12)

별도 검증 환경 `http://localhost:3002`에서 합성 사업 19 / 신청 20으로 다음 17개 API 흐름을 확인했다.

조건 미확인 추천, 다른 신청자·미배정 담당자 조회 차단, 업로드·연결, 신청자 확인 차단, 동시 수정 충돌, 다른 사업 파일 연결 차단, 확인된 답변 기반 미해당 추천, 다른 분야 검토 차단, 사유 없는 보완 차단, 미첨부 확인 차단, 보완→재첨부→확인, 배정 인프라 업로드·확인, 조건 변경 재검토, 관리자 확인 우회 차단, 제출 후 변경 차단, 감사 이력.

백엔드 전체 check와 프론트 전체 check(379개 테스트) 통과. 화면 컴포넌트 검사로 명시적 파일 연결, 신청자 확인 버튼 부재, 담당자 보완 사유 필수, 충돌 후 입력 보존을 검증했다. 실제 Chrome 수동 조작 검증은 이번 기록에 포함하지 않는다.

공공 GitLab과 기존 제출 환경(3001/8081)은 변경하지 않았다.

### Chrome 실제 화면 후속 검증

같은 검증 환경의 합성 신청 20에서 2026-11-12 실제 Chrome 화면을 조작해 다음 흐름을 확인했다.

- 신청자 `an.dw`: 초안 업로드·연결 → 정보보안 담당자 `jung.ys`: 사유를 적어 보완 필요 저장 → 신청자: 보완본 업로드·연결 교체 → 검토 중으로 전환.
- 정보보안 담당자: 연결된 보완본의 원문 팝업에서 합성 사업 범위·모의 이용자 100명을 확인 → 확인 사유 입력 → 확인 완료 저장. 파일 교체·보완·확인 담당자와 시각은 처리 이력에 보존됐다.
- 신청자: 클라우드 사용을 아니요에서 예로 변경 → 기존 확인 완료가 검토 중으로 돌아가고 재검토 안내·이전 확인 기록이 표시됐다. 클라우드 검토자료는 미해당에서 미첨부로 전환됐다.
- 신청자는 확인 완료 버튼이 없으며, 정보보안 담당자는 정보보안 자료만, `kim.dh`는 인프라 자료만 편집·검토할 수 있었다. `park.sy`는 신청 20 조회가 차단됐다. `moon.sw`는 자료·이력 조회만 가능하고 업로드·조건 변경·검토 버튼은 없었다.

업로드 성공 후 파일 이름이 입력창에 남아 같은 파일을 다시 선택하기 어려운 문제를 발견했다. 성공 시 실제 파일 입력을 초기화하고 전송 중 선택을 잠갔다. 수정한 검증용 Docker 화면에서 보완본 업로드 후 ‘선택된 파일 없음’으로 초기화되는 것을 확인했다. 같은 파일 재선택·재업로드 회귀 검사를 포함해 프론트 `npm run check` 380개 테스트와 규칙 문서 9종 검사를 통과했다.

최종 합성 신청은 조건 변경 후 재검토가 필요한 상태로 남겼다. 이 기록은 실제 기관 자료나 운영 신청을 사용하지 않았으며, 공공 GitLab과 기존 제출 환경은 변경하지 않았다.
