# 문서와 답변 간 모순 확인

2026-11-12 · GitHub 전용 개선. 공공 GitLab 및 제출 환경은 변경하지 않는다.

## 사용 방법

신청 상세 → 기관 기준 자동 점검 → 문서와 답변 간 모순 확인 → **AI 모순 확인**을 누른다. 입력 중인 답변은 먼저 저장한다. 후보의 저장 답변·원문 인용·설명을 대조하고 **원문 근거 확인**으로 첨부를 확인한다. 수정은 기존 답변 편집 영역에서 본인에게 허용된 항목만 수행하고 재검사한다. 기관 기준 충족 여부 검토와 모순 검사는 서로 다른 작업이다.

## 범위와 제한

- 현재 신청에 적용되는 사업 공통·서류별 저장 답변과 최근 첨부 3개의 추출문(파일당 최대 20,000자)을 비교한다. 화면에 검사 시각·파일 목록·전체/검사 파일 수·잘림/빈 텍스트를 표시한다.
- 미저장 입력, 별도 서버 구성표·운영 계획, 최종 보고서 본문, 과거 제출본은 비교 대상이 아니다. 제출 후에도 이 기능은 현재 저장 답변 기준이며 제출본을 재판정하지 않는다.
- AI가 찾은 것은 확인 후보다. 원문이 최신 정답이라고 단정하지 않으며, 후보 0건도 무모순 보증이 아니다. 누락·표현 차이는 모순으로 판단하지 않도록 요청한다.
- 답변·확인 상태·제출 상태를 자동 변경하거나 제출을 차단하지 않는다. 후보 확인·해소 이력의 영구 저장은 이번 범위에 포함하지 않는다. 기존 답변 수정 이력과 AI 호출 감사 기록은 유지한다.
- 실제 모델의 DOCUMENT 용도를 사용한다. 모의 모드·근거 검증 실패·빈 원문을 성공이나 후보 0건으로 표시하지 않는다.

## API와 보호

`POST /api/security-requests/{id}/consistency-checks` (본문 없음, CSRF 필요).

기존 신청 조회 권한·첨부 소속을 적용한다. 서버가 답변 키·파일 ID·원문 인용의 실제 포함 여부 및 설명의 근거 없는 IP를 검사한다. 일치하지 않으면 전체 결과를 거부한다. 문서 속 지시는 데이터로 다룬다. AI 호출 전후 전체 입력 지문과 권한을 다시 확인하고 변경됐으면 409로 재검사를 요청한다. 화면에서 답변이 갱신되면 이전 결과를 초기화한다. 결과는 저장하지 않으며 화면에 검사 당시 기준임을 명시한다. 긴 AI 요청에는 기존 660초 중계 제한을 적용한다.
