# 문서 검사·처리 이력과 최종 검토

2026-11-12 · GitHub 개발본 및 검증용 도커 전용. 공공 GitLab·기존 제출 환경은 변경하지 않는다.

## 사용 방법

신청 상세의 기관 기준 자동 점검에서 문서를 선택하고 **AI 모순 확인**을 실행한다. 저장된 공통·서류 답변, 서버·네트워크·운영 정보와 최종 초안 본문을 첨부 원문과 대조한다. 화면은 파일마다 순차 호출하며 앞선 파일의 완료 기록은 뒤 요청 실패 시에도 남는다.

**검사·처리 이력**에서 검사 당시 값·인용문·근거 파일을 확인한다. 현재 배정 담당자는 자신의 분야 또는 신청자 항목에 대해 확인·해소, 모순 아님, 보완 요청, 확인 필요로 재개를 사유와 함께 기록한다. 다른 분야 항목은 읽기만 가능하다. 판단은 누적 이력이며 AI 후보를 자동 확정하거나 답변을 덮어쓰지 않는다.

보완 요청은 기존 보완 업무로 연결되며 신청자 알림·처리할 일, 답변 후 현재 담당자 알림과 해소 절차를 사용한다. 읽음은 해소가 아니다. 계정·배정 권한은 요청마다 서버가 검사한다. 자료가 변경되면 과거 판단을 삭제하지 않고 재검사를 안내하며 오래된 검사에 새 판단을 저장하지 못한다.

## API·경합 보호

- POST `/api/security-requests/{id}/consistency-checks`: 선택 본문 `{fileIds:[...]}`. 생략 시 최대 20개 전체, 반환 전 입력 지문 재검사 후 기록 저장.
- GET 같은 경로 `?page=0`: 최신순 10건. 전체 기록은 페이지 이동으로 조회.
- POST `.../consistency-checks/{checkId}/decisions`: `expectedRevision`, `expectedFingerprint`, `findingIndex`, `status`, `reason`. 신청·사업·기록 잠금, 현재 배정·분야 검사, 409 충돌 응답.
- 판단 상태: OPEN, RESOLVED, DISMISSED, SUPPLEMENT_REQUESTED. 저장 행위와 감사 이력을 같은 트랜잭션으로 처리.
- 제출 시 모든 검사·처리 기록을 `snapshot.consistencyReviews`에 보존한다. 준비자료 묶음은 `snapshot.preparationReview`에 보존한다. 제출 이후 문서에는 이 고정값만 사용하며 없는 과거 기록을 추정하지 않는다.

## 최종 검토 중 변경

필수 항목, 담당자 항목, BOOLEAN·DATE_RANGE·IP_ADDRESS·PORT·PROTOCOL 값 또는 서버·네트워크·운영 구성이 바뀌면 3단계에서 2단계 재협의로 돌아간다. 일반 저장·일괄 저장·AI 적용에 공통 이벤트를 사용한다. 기존 값·제출본·반환 이력을 보존하고 협의 기한·담당자 알림을 다시 연다. 같은 값 재저장이나 최종 초안 문장 편집만으로는 재협의를 열지 않는다. 서류에 적용되지 않는 항목은 제외한다.

## 출력·관리자 정책

기존 방화벽·보안성검토 항목과 확인 상태·출처를 PDF 및 표 형태 DOCX로 출력한다. DOCX는 관리자 기관 설정의 서류 구성에서 허용하고 게시한 뒤 만든 신청부터 사용할 수 있다. 과거 신청은 자신의 게시본 출력 정책을 유지한다. 별도 공식 양식의 고정 좌표·HWPX 매핑은 후속 공식 양식 제공 시 진행한다.

관리자는 기존 질문 편집에 더해 서류 이름·설명·활성 여부·순서·출력 형식, 협의 분야, 기한 임박 일수(1~30영업일)를 편집한다. 초안 저장·검증·변경 비교·게시·이력·revision 충돌 보호를 재사용한다. 서버 기본 필드의 권한 계약과 필요한 검토 분야는 우회할 수 없다.

## 스캔 문서·검사 범위

PDF 텍스트가 없는 페이지를 로컬 Tesseract(kor+eng)로 인식한다. 원본을 바꾸거나 OCR만을 위해 외부 AI로 전송하지 않는다. 인식문에는 원본 쪽 번호와 **OCR 인식문·원본 대조 필요**를 표시한다. 이후 사용자가 AI 분석·검사를 요청하면 추출문은 설정한 모델로 전달된다.

일반 PDF 최대 100쪽, OCR 최대 8쪽/파일, 페이지별 12초, 동시 추출 최대 2건으로 제한한다. 텍스트가 일부 있는 이미지 페이지·표·손글씨의 인식은 완전하지 않다. 파일당 추출 최대 20,000자이며 잘림 여부를 표시한다. 긴 문서는 나누어 첨부하고 원본을 직접 대조한다. 모순 0건은 사실 정확성의 보증이 아니다. 최근 3개 제한은 제거했지만 전체 파일을 반드시 선택했는지는 사용자가 확인해야 한다.

도커 이미지에 Tesseract와 한국어·영어 언어팩이 포함된다. 직접 Java 실행 시 같은 도구를 PATH에 설치해야 한다. 미설치·시간 초과·빈 추출·모델 실패를 성공으로 표시하지 않는다. Tesseract는 Apache-2.0, Leptonica는 BSD 계열이며 배포 이미지의 `/usr/share/doc/*/copyright`에 배포판 패키지 고지가 유지된다.

## 검증

백엔드 전체 check 및 API 계약 검사, 프론트 전체 check를 수행한다. 검증 도커(3002/8082) 합성 사업20·신청21에서 실제 DeepSeek DOCUMENT 모델로 모순 생성, 판단 누적·경합·권한 차단, 보완 요청·답변·해소, 알림·처리할 일, 준비자료 재첨부·확인, 기간 변경 재협의와 INFRA 선행, 제출본8의 준비자료·검사 이력 보존, PDF·DOCX 문서8 다운로드를 확인했다. 스캔 PDF 한글 인식·쪽 표시와 원본 바이트 보존도 확인했다. 별도 신청22는 실제 화면 검증용이다.

### 브라우저 검증 상태

Chrome에서 신청22의 후보·원문 근거 창·판단 입력 화면을 확인했다. 저장 재시도는 브라우저 주소 확인 제한으로 중단되어 화면 저장 완료로 보고하지 않는다. 사용자 요청으로 남은 브라우저 검증은 보류하고, 통과한 자동 검사와 합성 API 통합 검증을 병합 기준으로 사용한다.
