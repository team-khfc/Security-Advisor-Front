# 현재 구현의 한계와 후속 연결

기록일: 2026-11-09. 이 문서는 Front에서 구현된 동작, 모의 동작, 아직 연결·검증하지 않은 범위를 구분한다. Back의 구현 현황은 최신 인수인계 문서를 참조한다. 실행하지 않은 검사를 통과한 것으로 보고하지 않는다. 최신 실행 결과는 해당 PR의 검증 기록을 따른다.

## 모의 API와 실제 Back

| 항목                      | 현재 상태                                                                                        | 다음 연결 또는 검증                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 독립 Front 개발           | 동일 출처 HTTP를 거치는 서버 메모리 모의 API 제공. 합성 데이터로 업무 화면·권한·충돌 흐름을 개발 | 확정된 Back OpenAPI에 맞춰 화면 DTO·Query 훅을 연결                 |
| 실제 인증·가입            | 현행 Back의 로그인·로그아웃·현재 사용자·회원가입 경로에 대한 프록시와 응답 어댑터 구현           | 실제 서버·세션 쿠키·CSRF와의 통합 실행 검증 필요                          |
| 실제 업무 API             | Back 12d89ed의 확정 OpenAPI·인수인계 문서 확인. 현재 Front 모의 DTO·경로와 차이가 있음                            | DTO·revision·조회 경로·업무 mutation 어댑터와 전 흐름 통합 검증                   |
| 설치 정보·관리자 회원 API | 기관 정보 `{name, code}` 변환 반영. 관리자 회원 목록·역할 변경은 후속 연결                          | 실제 회원 식별자·계정 조회·역할 변경 계약 반영                        |
| 데이터 보존               | 프로세스 메모리. 재시작 시 합성 seed로 초기화                                                    | 실제 영속성은 Back·DB 책임. 운영 저장소·다중 인스턴스·장애 복구 대체 불가 |
| 감사·업무 갱신            | 모의 모델의 같은 상태 갱신에 업무 결과와 감사 추가를 결합                                        | 실제 DB 트랜잭션·불변 감사 저장·보관 정책은 Back에서 구현·검증            |

현재 실제 모드는 연결용 경계이며, 전체 업무 화면의 실제 연동 완료를 뜻하지 않는다. 기관 정보·인증 연결을 준비했고, 사업·신청·답변·협의·제출 등 화면의 DTO와 저장 경로는 Back 확정 계약에 맞춰 추가 연결해야 한다. 실제 모드의 오류를 모의 성공으로 대체하지 않는다. 기동과 기본 연결 검사는 [테스트 서버 문서](BACKEND_TEST_SERVER.md), 계약 차이는 [계약 기록](../contract/README.md)을 참조한다.

새 신청·인터뷰·분석·답변 작성 중 입력은 [계정·자원별 탭 메모리](../lib/inputDrafts.ts)에 임시 보존한다. 같은 탭에서 같은 계정으로 화면에 돌아오면 복원하고, 다른 계정에는 표시하지 않으며 저장·생성·제안 적용 성공 후 해당 초안을 해제한다. 선택 파일도 [업로드 메모리](../lib/uploadDraft.ts)와 입력 초안에 일시 보관한다. **새로고침·탭 종료 후 입력과 파일의 복원을 보장하지 않는다.** 서버에 저장하지 않은 입력의 영속 보관이나 모든 대화상자 입력의 복원을 제공하는 기능은 아니다.

모의 분석은 파일을 해석한 결과가 아니고 내부 IP·시스템명을 추정하지 않는다. 반환 값은 사람이 확인하기 전까지 AI 미확정 값이다. [모의 분석 API](../mocks/server.ts)와 [문서함](../features/document/DocumentList.tsx)이 분석·출력의 경계를 표시한다.

## 운영 기능 범위

정책 수명주기는 확정 규칙 조회·적용 완료·적용 불가·회수 기록·별도 연장 신청을 Back API에 연결했다. 만료 예정·만료 표시는 서버 계산값을 사용한다. 트래픽 수집·자동 회수·연장 알림과 업무 지표는 후속 범위다. 화면 안 업무 인계·기한 알림, 읽음·페이지 조회와 처리할 일은 연결했으며 [알림 검증 기록](NOTIFICATIONS_20261110.md)을 참고한다. **서류 확정은 실제 방화벽 적용이 아니다.** 방화벽 장비 제어 기능은 없다. 합성 건의 실제 화면 검증은 [정책 수명주기 기록](POLICY_LIFECYCLE_20261110.md)을 참고한다.

기관 설정의 질문·기한 정책 편집, 초안 저장·검증, 변경 비교·게시 이력과 동시 수정 충돌 처리를 연결했다. 기존 사업 건과 그 사업에 추가하는 신청은 원래 게시본을 유지한다. 실제 사용자 흐름은 [기관 설정 검증 기록](CONFIGURATION_PUBLISHING_20261110.md)을 참고한다. 문서 양식 파일·점검 기준·검토 단계의 편집과 LLM 연결 구성 관리는 이번 구현에 포함되지 않는다. 기관 테이블이나 다중 기관 전환 기능은 향후 과제가 아니라 프로젝트 범위에서 제외한 구조다.

모의 세션의 만료 경고·연장은 구현되어 있으나, 실제 Back 응답에는 `expiresAt`이 없다. 실제 모드에서 가짜 만료 카운트다운을 만들지 않으며, 세션 연장 API와 실제 회원 식별자·부서·활성 상태 응답은 별도 계약이 필요하다. 인증의 현행 동사 경로 예외도 [계약 기록](../contract/README.md)에 남긴다.

목록 훅은 현재 최대 100건을 읽은 뒤 화면에서 검색·기간·상태 필터와 페이지 이동을 수행한다. 이는 대규모 데이터의 서버 검색·페이지 처리 구현이 아니다. 대량 신청·감사 이력·회원 목록은 실제 계약의 필터·정렬·커서 또는 페이지 정책으로 전환해야 한다.

## 검증이 남은 영역

| 검증 영역      | 남은 확인                                                                                                                   |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 실제 Back 통합 | 실제 세션·CSRF·쿠키 만료, 전 업무 API·ProblemDetail·revision 충돌, 제출 멱등성·동시 변경                                    |
| 실제 문서      | 파서 정확성·오류 문서·대용량·보안 검사, HWP·PDF 레이아웃·인쇄·다운로드                                                      |
| 전체 배포      | 별도 Security-Advisor 저장소의 Back·Front 릴리스 스냅샷과 통합 Docker Compose 실행. Front 단독 빌드는 전체 배포 검증과 구분 |
| 접근성         | 실제 화면 낭독기, 모든 역할·화면의 키보드 탐색, 확대 배율·고대비·모바일 보조기술을 포함한 수동 평가                         |
| 시각 일치      | 모든 화면·상태·뷰포트 조합의 디자인 검수. 본문 17px 보정에 따른 의도된 밀도 차이는 [디자인 기록](DESIGN_PARITY.md)에 명시   |
| 운영 품질      | 실제 트래픽 성능·부하, 여러 서버의 세션·저장 일관성, 운영 모니터링·백업·장애 복구·기관 보안 점검                            |

네이티브 dialog, 라벨·표 제목·포커스, 의미 있는 링크와 오류 안내를 작성했다는 사실과 보조기술 검증 완료는 구분한다. 프록시의 허용 헤더·요청 크기 제한·타임아웃도 전체 보안 검토를 대체하지 않는다.

후속 구현은 [FUNCTIONAL_SPEC.md](../FUNCTIONAL_SPEC.md)의 P1 수용 기준과 P2 착수 조건을 따른다. 이 문서 자체가 추가 범위의 승인이나 일정 변경을 의미하지 않는다.
