# 상시 규칙 재검토·준비자료 최종 검토 연결

2026-11-12 · GitHub 개발본 및 검증용 환경 전용

## 변경 범위

- 상시 운영의 `9999-12-31` 종료일을 정책 도메인의 종료일 없음으로 해석하고 시작일 + 12개월 재검토일을 생성한다. 기존 규칙은 새 Flyway 마이그레이션으로 보정하며 기존 재검토일, 제출본, 실제 장비 적용 기록은 보존한다.
- `GET /api/security-requests/{id}/preparation-materials/final-review`는 현재 조회 권한으로 자료별 적용 여부·상태·재검토 여부·최근 작성자와 시각·사유·파일 식별자와 이름을 반환한다.
- 제출 시 `snapshot.preparationReview`에 같은 묶음을 저장한다. 제출본·확정본 문서와 PDF는 이 고정 기록만 사용하며, 과거 제출본의 없는 기록을 현재값으로 보충하지 않는다.
- 준비자료 확인은 서류 승인이 아니다. 권고 자료의 미첨부만으로 제출을 차단하지 않으며, 자료 현황 기록을 미확정 AI 답변으로 집계하지 않는다.
- 보완 필요 검토는 신청자에게 `PREPARATION_SUPPLEMENT`, 첨부·재첨부·추가 조건 변경은 해당 분야의 현재 배정 담당자에게 `PREPARATION_REVIEW` 알림을 보낸다. 기존 계정 활성·역할·배정 권한 필터를 재사용한다.
- 처리할 일은 현재 자료 상태에서 계산한다. 신청자에게 보완 필요 자료, 담당자에게 첨부된 검토 중 자료를 표시한다. 제출·종료·미해당 자료는 제외하고, 재배정 후에도 현재 담당자에게 업무가 나타난다. 읽음 처리는 업무 완료로 간주하지 않는다.

## 검증 및 후속 범위

자동 검사: 상시 날짜 해석, 제출 스냅샷, 상태·파일 메타데이터 보존, 수신자, 처리할 일 집계, 과거 제출본 처리 및 여러 페이지 PDF의 긴 검토 사유 보존을 검사한다. `./gradlew spotlessApply check`와 OpenAPI 계약 검사를 적용한다.

사용자 요청에 따라 실제 브라우저·합성 신청의 통합 검증은 P1 묶음 구현 완료 후 수행한다. 이번 변경을 실제 화면 검증 완료로 해석하지 않는다. 모순 후보의 처리 결과 저장·해소 관리는 이번 범위에 포함되지 않으며 후속 구현 대상이다. 재검토 주기는 기존 12개월 고정 정책을 유지한다.

후속 통합 검증: 상시 규칙 재검토일 및 알림 → 준비자료 보완 요청 → 재첨부 → 담당자 확인 → 조건 변경 재검토 → 신청자 최종 검토 → 제출 이후 자료 변경과 독립된 제출본·PDF 확인 → 재배정·역할 변경 권한 확인.

공공 GitLab, 완성본 배포 저장소, 기존 제출용 Docker 환경에는 적용하지 않는다.
