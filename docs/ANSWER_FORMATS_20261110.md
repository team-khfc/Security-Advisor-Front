# 답변 형식과 미해당 저장

## 검토 결과와 변경

기존 TEXT/LONG_TEXT/BOOLEAN/NUMBER/DATE_RANGE 검증에 IP_ADDRESS, PORT, PROTOCOL을 추가한다. 관리자 질문 초안에서 형식을 선택하고 게시하면 새 신청에 적용한다. 기존 게시본 및 기본 질문 계약은 자동으로 변경하지 않는다.

| 형식 | 허용 |
| --- | --- |
| IP_ADDRESS | IPv4, IPv6, CIDR (IPv4 0~32, IPv6 0~128 접두 길이) |
| PORT | 1~65535, 오름차순 시작-종료 범위 |
| PROTOCOL | TCP, UDP, ICMP, ICMPV6, ESP, AH, GRE |

쉼표 또는 줄바꿈 목록을 최대 100개 허용한다. DNS 조회·장비 연결 없이 리터럴만 검사한다. 호스트명, IPv4 축약·앞자리 0, 잘못된 접두 길이·역전 포트 범위·알 수 없는 프로토콜은 422다. 기존 4000자 상한과 작성·확인 역할 및 배정 검사를 유지한다.

## 미해당 계약

- 선택 항목만 `notApplicable: true`를 저장할 수 있다. 값은 생략·빈 문자열로 전송한다. 일반 값과 동시에 보내면 422다.
- `answers.not_applicable` 컬럼과 응답·새 제출본 스냅샷에 별도 상태를 보존한다. 기존 문서 표시 호환을 위해 `value`는 `미해당`으로 정규화한다.
- 기존 클라이언트의 `미해당` 문자열 입력도 선택 항목에 한해 정식 상태로 변환한다. 새 필드를 생략한 일반 입력은 종전대로 처리한다.
- 신규 마이그레이션은 기존 출처 있는 `미해당` 답변을 이관한다. 기존 제출본 JSON은 수정하지 않는다.
- 일반 값을 다시 저장하면 미해당은 해제된다. 출처·확인·재검토는 별도 속성으로 유지한다. AI 미해당 제안은 사람 확인 전 미확정이다.
- 개별/일괄, 신청자/담당자, AI 적용 경로가 같은 정책을 사용한다. 일괄 요청은 전체 성공 또는 전체 롤백하며 revision 충돌은 409다. 제출 직전에도 게시본 형식을 검증한다.

## 검증

- 프론트 `npm run check`: 테스트 332개와 포맷·타입·린트·문서 기준 검사 통과.
- `gradlew spotlessApply check`: 201개 중 199개 통과, 실제 모델 연결용 조건부 테스트 2개 제외, 실패 0. 문서 기준 검사 통과.
- 단위/API 검사: IPv4/IPv6/CIDR/포트 경계, 미해당 전환, 권한·충돌·재조회, AI 잘못된 포트 거부 및 미해당 미확정 유지.
- 전용 Docker(3014/8094): 합성 게시본 v4, 신청 4·5로 API 20개 검증. 신청자·INFRA·SECURITY 정상 저장, 권한 차단, 잘못된 입력·필수 미해당·모순 입력 거부, 일괄 롤백, 기존 신청 2의 게시본·답변 보존.
- 실제 화면: 잘못된 포트 65536 차단 → 미해당 저장 → 새로고침 유지 → 443, 8000-8080 재입력 → 미해당 재전환 확인.
- 기본 연동 환경(3001)의 데이터와 실제 모델 구성은 변경하지 않았다. 실제 장비 변경은 없다.
