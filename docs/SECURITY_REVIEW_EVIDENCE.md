# 보안성검토 전용 질문과 첨부 원문 확인

2026-11-12 · 제출 후 GitHub 전용 개발. 공공 GitLab 제출본은 변경하지 않는다.

## 적용 방법

기존 게시본·신청을 마이그레이션으로 덮어쓰지 않는다. 프론트와 백엔드를 함께 배포한 뒤 관리자가 **기관 설정 → 인터뷰 질문 → 보안성검토 전용 질문 추가 → 설정 초안 저장 → 변경 검토·게시**를 실행한다. 게시 이후 생성한 사업부터 적용된다. 기존 사업에서 추가한 신청도 기존 게시본을 유지한다.

질문 묶음은 개인정보 처리, 외부 전송, 대외 서비스, 외부 업체 참여 조건을 사용한다. 개인정보 처리 내역은 신청자, 백업·복구 및 운영 책임은 ICT인프라, 보호조치·외부 전송·대외 서비스·업체 통제·종합 의견은 정보보안 담당자가 작성한다. 기관 정책의 법적 적합성을 자동 판정하는 기능은 아니다.

## 조건과 업무 규칙

- 게시본의 `FieldDefinition.condition`은 선택 속성 `{ fieldKey, expectedValue }`이다. 기존 게시본에서 생략하면 항상 적용된다.
- 조건의 대상은 같은 서류에 적용되는 **신청자 필수 CASE BOOLEAN 질문**이어야 한다. 조건의 조건, 자기 참조, 없는 질문, 범위 불일치는 게시 전에 거부한다.
- 미입력 조건을 ‘예’나 ‘아니요’로 추정하지 않는다. 부모 질문의 필수·미확정 검사는 제출 시 그대로 적용한다.
- 개별·일괄 저장·확인·AI 추천 적용은 같은 조건 검사를 사용한다. 적용되지 않는 질문의 새 입력은 거부한다. 기존 답변은 삭제하지 않지만 제출 필수 검사·AI 컨텍스트·문서 표시에서는 제외한다.
- 담당자 전용 REQUEST 필수 질문은 해당 분야 협의 완료 전 값과 확인 상태를 검사한다. 기존 공통 인프라 항목은 인프라 계획 검사를 유지한다.
- 담당자 입력은 기존 협의 기준본·변경 이력에 기록되며, 신청자 최종 검토와 제출본 문서로 이어진다. 제출본에 조건 답변과 근거를 보존하며 이후 현재값으로 과거 제출본을 재해석하지 않는다.

## 원문 API

- `GET /api/business-cases/{id}/source-documents/{fileId}`: 첨부 원문에서 추출한 텍스트, 파일명·업로드 시각·표시 한도를 반환한다. AI 요약이 아니다.
- `GET /api/business-cases/{id}/uploaded-files/{fileId}`: 원본 바이너리를 첨부 다운로드로 반환한다. 업로드 MIME을 그대로 실행하지 않으며 `no-store`, `nosniff`를 적용한다.
- 두 API 모두 사업 조회 권한과 파일의 사업 소속을 검사한다. 다른 신청자와 미배정 담당자는 읽을 수 없다.
- 추출문은 기존 추출기 기준 앞 20,000자까지 표시한다. 줄 번호는 추출문 기준이며 원본 페이지 번호가 아니다. 이미지·스캔 문서 등 추출 불가 시 원본 다운로드로 확인한다.
- 새 인터뷰·담당자 질의의 문서 근거에는 서버가 결정한 파일 ID가 포함된다. 프론트는 명시된 ID만 연결한다. 이전 순번 근거를 현재 파일 목록에 맞춰 추정하지 않는다.
- 원문 확인은 답변 확정이나 협의 완료를 자동 실행하지 않는다. API 키·원문은 감사 로그에 추가하지 않는다.

## 검증

분리된 Docker 프로젝트 `security-advisor-security-review`에서 3002/8082 포트와 별도 DB·문서 볼륨을 사용한다. 제출 환경 3001/8081과 GitLab에는 쓰지 않는다.

합성 게시본 v1 유지·v2 적용, 조건 해당/비해당, 신청자/담당자 작성 권한, 원문 접근 권한, 담당자 필수값 누락 차단, 비해당 질문 문서 제외를 점검한다. 조건과 문서 렌더링 단위 테스트, 원문 조회 권한·추출문 테스트를 포함한다. 실행 결과는 동반 PR에 기록한다.

### 2026-11-12 실행 결과

- Back `spotlessApply check`: 233개 테스트, 실패 0. Front `npm run check`: 50개 파일의 375개 테스트 및 타입·린트·문서 검사 통과.
- 합성 v2 사업 16/신청 17(조건 해당), 사업 17/신청 18(조건 비해당)을 사용했다. 기존 v1 사업의 버전 유지를 확인했다.
- API: 다른 신청자·미배정 담당자의 원문 조회 404, 신청자의 담당자 항목 수정 및 다른 분야 수정 403, 비해당 질문 저장과 담당자 필수 질문 누락 협의 완료 422를 확인했다. 첨부 원본 바이트와 추출문 일치도 확인했다.
- 실제 Chrome: ICT인프라 백업·복구 답변 작성·저장·협의 완료 → 정보보안 종합 의견 작성·저장·협의 완료 → 신청자 변경 전후·작성자·시각 검토 → 최종 보고서 직접 작성·확인 저장·제출 → 제출 문서 미리보기·PDF 다운로드를 확인했다. 제출본 7의 조건별 검토 7항목과 근거 속성 보존을 API로 재확인했다. 화면에서 받은 PDF와 API PDF는 각각 26,110바이트였다.
- 원문 모달의 파일명·업로드 시각·줄 번호·원본 다운로드 링크와 리터럴 `<script>` 표시를 실제 화면에서 확인했다. 추출문은 HTML로 실행되지 않았다.
- 실제 DeepSeek 문서 분석·인터뷰 결과에 서버가 지정한 `파일 #2` 근거가 포함되는 것을 확인했다. AI 요약은 미확정 참고자료로 표시된다.
- 발견한 표시 문제: 조건값 `true/false`를 `예/아니요`로 표시하고 전용 검토 결과를 기본 펼침으로 변경했다. 새 제출본에는 답변 근거를 보존하며 과거 제출본의 없는 근거는 추정하지 않는다.
- 제한: 최종 제출 후 AI 대화의 직접 근거 링크를 추가로 클릭하려는 시점에 Windows 브라우저 URL 확인이 실패해 화면 조작이 종료됐다. 해당 링크의 파일 식별자 연결·원문 조회·검색 동작은 자동 테스트로 검증했으나 이 마지막 직접 링크 클릭은 실제 화면 완료로 보고하지 않는다.
