## 이번에 반영한 기준

- 신청자는 본인, 담당자는 현재 역할·분야의 활성 배정 신청만 조회한다. 목록·상세·문서·이력·방화벽 규칙에 같은 범위를 적용하며 관리자 조회는 담당자 검토 권한이 아니다.
- 계정 비활성화·역할 변경은 기존 세션을 회수한다. 재활성화·역할 원복으로 옛 세션이 살아나지 않는다.
- 독립된 자원 할당 완료 단계는 없다. 구성 입력·임시 저장은 협의 완료가 아니며 기본 두 서류에서 INFRA 협의 완료 후 SECURITY 협의 완료가 가능하다.
- AI는 제안하며 사람이 확인한다. 자료에 없는 값을 확정 사실로 채우지 않는다. 비공개 사실과 공개 지식의 범위를 구분한다.
- 공개 지식 검색은 항목 키와 PostgreSQL 전문검색(FTS) 기반이다. pgvector 이미지가 실행 구성에 있더라도 VectorStore·임베딩 검색을 구현했다는 뜻은 아니다.
- 재검토 범위·재신청·서류 유형별 확정 주체·방화벽 기간 등 남은 정책은 PROJECT_CONTEXT 8장에 유지한다. 이 가이드를 이유로 코드를 임의 변경하지 않는다.

## 수정·검사·반영

1. 최신 main에서 작업 브랜치를 만들고 변경 범위와 관련 규칙을 확인한다.
2. 기준 버전 표와 승인 기록을 확인한다. 숫자가 높은 미승인 사본을 자동 채택하지 않는다. 사본 동기화가 지연되면 PROJECT_RULES 7-1의 임시 적용 기록을 남긴다.
3. 기능은 Front·Back 원본에서 수정한다. API 변경은 Back의 OpenAPI 계약을 먼저 고치고 Front의 계약 사본·출처·타입·변환기·모의 API를 함께 맞춘다.
4. PR(GitHub)·MR(GitLab)에 변경 이유, 수행/미수행 검사와 관련 요청 링크를 남긴다. 이번 문서 반영은 양쪽 호스트에 각각 수행하며 자동 미러링을 가정하지 않는다.
5. 규칙을 개정하면 머리말·변경 이력·PROJECT_CONTEXT 기준표와 [출처 해시](SOURCE_PROVENANCE.md)를 함께 갱신하고 세 저장소에 동기화한다.

```bash
python3 tools/check_doc_versions.py
git diff --check
```

Windows에서는 설치된 Python 3 명령(`python` 또는 `py -3`)을 사용한다. 공식 원본 ZIP 해시와 수정 공개본 해시는 다를 수 있다. 승인된 수정에 따른 해시 갱신은 필요하지만, 의도하지 않은 파일 변경을 숨기기 위해 해시만 바꾸면 안 된다.

문서만 바꾼 경우 링크·명령·코드 일치와 문서 검사를 수행한다. 기능 변경은 각 저장소의 전체 검사와 필요한 업무 흐름 검증을 따른다. 한시 검사 축소는 제출 메일 발송으로 종료되며 발송 증빙이 없으면 전체 검사가 기본이다. 자동 CI가 추가 실행되면 결과도 확인한다.

개정 내역: [RULES_CHANGELOG](RULES_CHANGELOG.md). 과거 검증 보고서는 작성 시점의 결과이며 현재 버전 검증을 대신하지 않는다.
