# 방화벽 정기 재검토 사용 안내

2026-11-13 · GitHub 개발본 / 검증용 환경

1. **관리자 → 기관 설정 → 처리 기한·공휴일**에서 상시 방화벽 재검토 주기(1~60개월)와 알림 시점(1~90달력일)을 편집한다. 초안 저장 후 변경 비교·게시하고 설정 버전에서 이력을 확인한다. 기존 사업·규칙의 주기는 유지된다.
2. **ICT인프라 → 정책 수명주기**에서 ‘정기 재검토·후속 조치’ 필터로 대상을 찾는다. 규칙의 재검토일·임박/경과/후속 조치 상태를 확인하고 ‘기록·처리’를 연다.
3. **재검토 · 계속 유지 / 변경 필요 / 회수 필요**를 선택하고 사유를 작성한 뒤 확인하고 저장한다. 계속 유지는 오늘부터 다음 주기를 계산하며, 변경·회수 필요는 처리할 일에 남는다. 회수 필요 판단만으로 실제 회수 기록이나 장비 변경이 이루어지지 않는다.
4. 기록·처리 창에서 작성자·시간·사유·이전/다음 검토일을 확인한다. 동시 저장 충돌 시 입력을 유지하고 최신 상태를 확인한다.
5. **처리할 일**의 방화벽 재검토 카드에서 사업 정보와 규칙 번호·검토일을 확인하고 정책 수명주기로 이동한다. 담당자 비활성화·역할 변경 시 **관리자 처리할 일 → 신청 상세 → 담당자 재배정**으로 ICT인프라 업무를 인계한다. 기존 제출본·판단 이력은 유지된다.

백엔드가 현재 배정·역할·계정·규칙 상태·revision을 최종 확인한다. 확정 이후 인계는 적용 대기/적용 완료 규칙의 ICT인프라 담당자만 가능하다. 브라우저 실조작 검증은 보류했으며, 자동 화면 검사와 검증용 Docker API로 정책 편집·판단 저장·권한·인계를 검증했다.

디자인 참고: prototype-soo `563dd7e76aeeb4fe63f010bec9cd1f9bac16d5dc` 및 MERGE_NOTES. 기존 카드·필드·모달·오류 안내 컴포넌트를 사용한다. GitHub 외 제출 저장소와 기존 제출 도커는 변경하지 않는다.
