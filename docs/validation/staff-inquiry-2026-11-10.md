# 담당자 AI 질의 화면 검증 (2026-11-10)

## 구현과 기준

배정된 ICT인프라·정보보안 담당자가 신청 상세에서 개인 AI 대화를 생성·선택하고 계속 질문한다. 신청자 인터뷰와 분리하고, 검토 영역에서 바로 이동할 수 있게 했다. 질문·답변·근거는 넓은 대화 영역에 표시한다. 질문 예시는 입력만 채우며 답변을 검토 의견이나 신청 값에 자동 적용하지 않는다.

- F-04, 현행 규칙 문서 9종의 기준 버전 일치 확인.
- 시안: prototype-soo `563dd7e76aeeb4fe63f010bec9cd1f9bac16d5dc`의 신청 상세 구성·스타일·tokens와 MERGE_NOTES 기준. 기존 17px 본문과 입력, 카드·색상 토큰을 사용했다.
- 서버: [Back PR #8](https://github.com/team-khfc/Security-Advisor-Back/pull/8), 커밋 `9c0f7f24d7e940c6eb3fedc701ce7775f3be4df8`.
- 기존 inquiries / messages OpenAPI 경로·DTO 유지. 서버 보완을 먼저 적용한다.

## 자동 검사

- 포맷, 타입, 린트, 문서 기준 검사, 288개 테스트 통과.
- 프로덕션 빌드 통과. Windows 산출물 폴더 생성 제한으로 최초 로컬 빌드는 실패했으며 필요한 권한으로 재실행해 성공했다. 도커의 Linux 빌드도 성공했다.
- 새 대화 생성 후 응답 실패 시 같은 대화에서 재시도, 입력 보존, 빠른 중복 전송 방지, 질문 예시의 비자동전송, 계정별 응답 검사, 대화별 미전송 입력 분리를 검사한다.
- 모의 API도 배정·소유권을 검사하고 대화 외 업무 데이터가 변하지 않는지 검사한다.
- 질문을 모두 지우면 미저장 입력 표시도 해제한다.

## 도커 실제 사용자 흐름

합성 사업 17 / 방화벽 신청 29에서 실제 모델을 사용했다. 실제 장비는 변경하지 않았다.

1. 합성 텍스트 파일을 업로드하고 AI 분석을 완료한 뒤 협의를 요청했다.
2. ICT인프라 담당자가 키보드로 도우미에 이동하고 문서 근거 질문을 전송했다. 식별 문구 `별빛검증-731`, 기록 보관 180일, 사전 승인, HTTPS 443을 원문 U1·요약 D1 근거와 함께 확인했다.
3. Enter는 줄바꿈, Ctrl+Enter는 전송되며 완료 후 입력창에 초점이 돌아왔다. 후속 질문까지 4개 메시지가 저장됐다.
4. 새로고침·재로그인·도커 재배포 후에도 답변과 파일명·문자 범위·미확정 요약 근거가 유지됐다. 현재 검색에 없는 이전 근거를 AI가 재인용한 경우 확인 필요 경고가 표시됐다.
5. 정보보안 담당자에게는 INFRA 대화가 보이지 않고 별도 새 대화가 열렸다. 개인정보·접근 권한·기록 보관 질문에 미확정 사항을 구분한 답변과 5개 근거가 표시됐다. 인프라 할당 전에도 참고 질의는 가능하며 검토 완료와는 분리된다.
6. 신청자 화면에는 담당자 대화가 없다. API에서도 신청자·미배정 담당자는 403, 다른 소유자 메시지는 404였다.
7. 질의 전후 신청 상세 전체 응답이 동일했다. 검토 체크리스트는 0개 선택, 의견은 공란으로 유지됐다.
8. 390×844 화면에서 가로 넘침 없음, 본문·입력·선택 17px, 선택창 높이 48px를 확인했다. Tab, Space의 새 대화, 대화 선택, 키보드 대화 스크롤이 동작했다. 화면 점검 후 원래 크기로 복원했다.
9. `npm run test:connection`의 실제 로그인·세션·CSRF·프록시 검사 통과.

## 안내하는 한계

최근 업로드 3개, 앞 20,000자 중 최대 6,000자 발췌 및 요약 3개를 사용한다. 전체 문서 검색/OCR는 아니며, 자료 변경 후에는 다시 질문해야 한다. 미확정 AI 요약·근거 없음·확인할 수 없는 근거를 구분해 표시한다. 서버 장애·중복 전송·배정 해제·역할 변경은 자동 검사로 확인했고 실제 도커에서 관리자 배정을 바꾸거나 장애를 발생시키지는 않았다.
