# 목록·이력 검색과 권한별 실제 화면 검증

2026-11-10 · Front #44 / Back #9

## 구현

신청 현황, 문서함, 보완 요청, 통신 정보는 서버에 검색·필터·페이지를 전달한다. 표에는 현재 페이지를, 요약과 페이지 이동에는 전체 건수를 사용한다. 신청 현황은 서버 요약으로 담당자·처리 기한·다음 할 일을 표시하므로 전체 신청의 상세 자료를 미리 가져오지 않는다. 문서 등 상세 자료가 필요한 화면도 현재 페이지에 한정한다. 사업별 관련 신청은 해당 사업의 모든 페이지를 읽는다.

전체 이력과 신청 상세 이력은 페이지 API를 사용한다. 이력의 throughId를 페이지 이동에 유지하고 검색 변경/최신 조회 시 해제한다. 신청자에게 ‘내 신청 이력’ 메뉴를 제공하고, 업무 구분은 모든 서버 행위를 한국어로 표시한다. 계정별 캐시 키와 이전 데이터 표시 조건으로 계정 전환 시 다른 사용자의 목록이 섞이지 않도록 했다. 서버가 최종 권한을 검사한다.

## 실제 화면

도커에 일반 업무 API로 만든 `목록검증1110` 합성 신청 220건과 타인 소유 1건을 사용했다. 첫 신청 31번에는 전체 이력 146건(답변 변경 140건)이 있다. 기존 신청·볼륨을 유지했고 실제 장비 변경이나 AI 호출은 실행하지 않았다.

| 사용자 흐름 | 확인 결과 |
| --- | --- |
| 신청자 신청 검색·마지막 이동 | 220건, 44/44페이지, 가장 오래된 합성 신청 표시 |

좁은 화면 검사에서 브라우저 너비 재정의와 확대율 영향으로 실제 DOM viewport는 520px이었다. 페이지 버튼이 해당 너비 내에 배치된 것을 확인했으며, 390 CSS px 화면을 검증했다고 간주하지 않는다. 검사 후 너비 재정의는 해제했다.

모든 역할의 전체 페이지를 별도 HTTP 검사로 순회해 중복·누락 없이 신청자/담당자 220건, 관리자 221건, 타인 신청자 1건임을 확인했다. 이력 내용뿐 아니라 전체 건수에도 같은 권한이 적용된다. 사용자 입력 원문·비밀번호·AI 키는 검증 기록과 저장소에 포함하지 않았다.

## 범위

이번 브라우저 검증은 목록·검색·이력·관련 신청·문서 목록에 한정한다. 새 제출·반환·확정·PDF 생성·실제 장비 적용을 다시 수행하지 않았다. 보완 요청의 검색·페이지 계약은 구현했으며 이번 합성 220건에 새 보완 업무를 생성하지 않았다. 기존 단위/통합 검사에서 관련 업무 회귀를 확인했다. 도커는 PR 검토용 브랜치 상태이며 main에는 아직 병합하지 않았다.
